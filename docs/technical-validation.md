Run: **2026-09-23 02:53 UTC**, Windows NT **10.0.26200**, installed **Chrome 153.0.8010.52** and **Edge 153.0.4234.48**, real browser engines driven headlessly by the isolated Playwright harness. [Raw results](../spikes/browser-lab/results/desktop-results.json) and generated files are retained in the spike directory.

**PASS** means the named environment and test succeeded; **FAIL** means it ran and failed; **PARTIAL** means the scope or environments are incomplete; **NOT TESTED ON REAL DEVICE** and **REAL DEVICE TEST REQUIRED** never imply PASS. A browser feature described in documentation is not experimental evidence.

## Decision / recommendation after each spike

1. **Picker:** returned `FileList` order is observable; user click order is unproven. Keep the approved rearrangement flow. Do not describe order as click sequence.
2. **Decode:** JPEG/PNG/WebP work for named desktop fixtures. HEIC fails here. Candidate policies are client conversion, platform-specific support, or a JPG/PNG requirement; none is selected. iOS picker may return a transformed file and needs direct observation.
3. **Crop:** the Product Owner reported failed drag on the original test page. The follow-up desktop regression now drags both the blue crop viewport and upper preview while retaining coverage at 1.5×. On a just-filled image, the dimension with zero overflow cannot move until zoom increases. **iPhone drag and pinch require re-test; desktop success does not override the reported iPhone failure.** Production pointer/mouse drag, single-finger drag, pinch, explicit zoom, clamp and Reset remain hard requirements.
4. **Calendar/layout:** one January model produced correct date positions and nearly matched scaled preview/export pixels. The original isolated proof put an 800×1200 photo in the middle and left side gutters. Product Owner clarification resolves the earlier wording ambiguity: the **whole** output is 2:3, and its upper Photo Region must cover the complete width. The disposable page now uses a 1200×1044 upper region, matching the frozen prototype's 58% split for this experiment; no production geometry implementation is selected. Desktop PNG follow-up visibly has no side gutters. iPhone export fidelity requires re-test.
5. **Fonts:** official local TTFs can load and render into Canvas. OFL notices in `spikes/browser-lab/fonts/` permit embedding/bundling, subject to license obligations. The Product Owner reported no visible iPhone preview change between the three presets. The refined page exposes selected preset, face statuses, `document.fonts.status/check`, CSS computed family, Canvas font and fallback flag; no iPhone log or exported comparison has yet been returned. Desktop follow-up showed three different preview text-region hashes. Safari, WOFF2, and final preset selection remain pending. The Simplified Chinese Product UI font was not changed.
6. **PNG:** dedicated Canvas is an **ADR CANDIDATE**, not an architecture decision. The unembedded SVG path lost the chosen font in both tested browsers. Exact crop/text fidelity across preview/export needs target-device checks.
7. **iOS handoff:** the Product Owner tried both PNG download entrances and initially could not find the result, then located a downloaded PNG in **iCloud Drive → Downloads**. Correct the earlier FAIL: **at least one ordinary Safari file download succeeded**. Which entrance produced that file, its dimensions and whether both entrances worked remain unverified; the desktop user-activation comparison cannot settle those details. [Apple's iPhone download guidance](https://support.apple.com/en-au/102440) places Safari downloads in the Files app, not automatically in Photos. **Open PNG also works**, followed by a manual Save to Photos action, but the Product Owner explicitly requires one action to save directly into Photos. That requested outcome remains **FAIL / unresolved feasibility**, independently of the now-confirmed file download. iPhone ZIP generation was reported, without destination or integrity. LAN HTTP cannot settle Web Share; a trusted HTTPS URL remains **OPEN QUESTION**. The [Web Share specification](https://w3c.github.io/web-share/) permits file sharing to a **user-chosen** destination; it does not provide a specified direct Photos write or remove target selection. Apple's [PhotoKit guidance](https://developer.apple.com/documentation/PhotoKit/delivering-an-enhanced-privacy-experience-in-your-photos-app) describes an authorized **native-app** route for adding assets, including an initial permission step. These references are not device test results. An HTTPS Share Sheet test remains useful for delivery alternatives but **cannot be counted as satisfying the no-second-step requirement** merely because the sheet opens. **OPEN QUESTION / product-platform conflict:** whether the browser-only V1 constraint or the newly stated direct-Photos requirement changes; do not choose architecture or label the mobile gate passed until resolved.
8. **Batch:** sequential Canvas generation succeeded with one renderer Canvas at a time. JS heap during the earlier ZIP run rose roughly 12→32 MB in Chrome and 12→29 MB in Edge as PNG byte arrays accumulated; these variable measurements exclude GPU/native process memory. Product output is 12 independent PNGs; ZIP only packages them. Mobile completion was reported, but size, duration, interruption and handoff still need evidence.
9. **Persistence:** IndexedDB is a plausible **ADR CANDIDATE** for images plus settings. The Product Owner reported a successful iPhone restore, but mobile capacity with 12 large originals, quota failure, eviction and interruption remain unresolved. The CDP quota experiment cannot be cited as PASS.
10. **Tabs:** transaction-level revision guard rejected a stale write; a cross-tab signal also set a conflict flag. Still test browser suspension and Safari.
11. **Contrast:** relative-luminance comparison of `#1E211F` versus white chooses the higher ratio. `#777777` exposes a 4.48:1 boundary, below a 4.5:1 normal-text target. Pure black/white is a candidate if the Product Owner accepts the visual adjustment; Custom remains unchanged with a warning. Any baseline visual-system change must follow the AGENTS.md UI/UX change process.
